# 시연 영상 대본·장면 설계 (v0.1, 2026-11-08)

> 목적: 기획서의 핵심을 **말로 설명할 흐름**으로 먼저 정리한다. 디자인은 그다음.
> 구성: **가로 본편 약 1분 45초** + 같은 소재의 **세로 숏폼 45초** (본편 완성 후 컷 추출).
> 원칙: 실제로 확인된 것(에뮬레이터 값)과 목업(기획 화면)을 **화면에 구분 표기**한다. 확인되지 않은 것은 실제처럼 보이게 하지 않는다.
> 첫 20초 안에 "경고등 전에, 정차한 뒤, 가야 할지 말지를 가려준다"를 보여준다.

## 제작 현황 (11/8)
- **v1 완성**: `시연영상/차량주치의_시연영상_v1.mp4` (1920×1080, 1분 32초, 내레이션+자막 포함) + `.srt` 자막 파일
- 내레이션: PC 기본 한국어 음성(Microsoft Heami)으로 생성. 기계음이라 자연스러움은 제한적.

- 대본 변경: 장면 2는 "앱이 안전 정차 안내를 띄운다"가 아니라 **"차량이 앱 사용을 막는다"** 로 정정(실제 확인된 동작). 정차 안내 방식은 미확인이라 영상에서 단정하지 않음.
- **v2 세로 숏폼 완성(11/8)**: `시연영상/차량주치의_시연영상_숏폼.mp4` (1080×1920, 48초). 후킹 → 실제 D 차단 → 실제 D→P → 증상·주행거리 → 센터 점검 결과 → 진단서 → 4단계·차량 주치의. 상하단은 인스타 UI 안전 영역을 비워 둠.
- 미반영: 시나리오 A(전구·퓨즈), 실제 주행거리 값 화면(콘솔로 값 설정 가능성은 있으나 미시험).

## 0. 한 줄 메시지
"경고등이 켜지기 전, 이상한 느낌이 들 때 — **멈춘 뒤에** 센터에 갈 일인지 직접 고칠 일인지 가려주는 차 안 주치의"

## 3. 실제 장면과 목업의 구분
| 구분 | 내용 | 표기 |
|---|---|---|
| 실제 에뮬레이터 값 | 기어 P/D 변경(Virtual Console), 현재 주행거리, EV 배터리 등 | 화면 모서리 `에뮬레이터 실제 값` |
| 목업 | 증상 선택 화면, 트리아지 결과, 진단서, 센터 안내, 간단 조치 가이드 | 화면 모서리 `기획 화면(목업)` |
- 심사 기준이 "지정 에뮬레이터에서 동작"이므로, **목업을 실제 앱처럼 보이게 하지 않는다.** 2차 PT 전까지 실제 앱을 만든다는 계획을 자막 마지막에 한 줄.

## 5. 촬영 시 주의
- 에뮬레이터 창과 Pleos 프로젝트 정보(클라이언트 ID·시크릿이 보이는 화면)는 **녹화에 넣지 않는다.**
- 화면 녹화는 에뮬레이터 화면만 캡처한다. 브라우저의 Virtual Console은 필요한 부분(기어 버튼)만, 주소창·탭 제외.
- 샘플 앱 화면은 공식 샘플이므로 우리 서비스 화면으로 오해되지 않게 `공식 샘플 앱`으로 표기한다.
- 타이어 저압 값(137.0)은 의미 미확인이므로 숫자를 보여주지 않는다.

## 6. 선생님 확인 필요 (결정)
1. **내레이션 방식**: 직접 녹음 / 자막만. (자막만이면 편집이 단순하고 개인 목소리 노출이 없다)
2. **편집 도구**: PC에 ffmpeg가 없다. 설치해도 되는지, 또는 사용 중인 편집 프로그램(예: 캡컷, 프리미어)이 있는지. 없으면 클립·이미지·자막 파일을 준비해 드리고 조립은 직접 하시는 방식도 가능.
3. 서비스명 `차량 주치의 (Car Doctor)` 확정 여부 (자막·표지에 들어감)
4. 시연 영상은 가산점(선택)이므로 **기획서 확정이 우선**. 일정상 영상은 11/12까지, 11/13 제출 권장.
