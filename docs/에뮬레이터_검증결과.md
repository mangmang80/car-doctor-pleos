## 2. 에뮬레이터 차량 속성 목록 조회 (adb dumpsys car_service)
- 총 **337개** 속성 등록 (표준 AAOS + 벤더 속성).
- 표준 속성으로 확인된 것(주요):
  - **주행 상태**: PARKING_BRAKE_ON, GEAR_SELECTION, CURRENT_GEAR, PERF_VEHICLE_SPEED, TURN_SIGNAL_STATE
  - **주행거리·연료·배터리**: PERF_ODOMETER, FUEL_LEVEL, FUEL_LEVEL_LOW, EV_BATTERY_LEVEL, EV_CURRENT_BATTERY_CAPACITY
  - **타이어**: CRITICALLY_LOW_TIRE_PRESSURE, TIRE_PRESSURE_DISPLAY_UNITS
  - **램프·와이퍼**: HEADLIGHTS_STATE/SWITCH, HIGH_BEAM, HAZARD, CABIN, READING, WINDSHIELD_WIPERS_STATE/SWITCH
  - **차체**: DOOR_POS, DOOR_LOCK, WINDOW_POS, GLOVE_BOX_DOOR_POS, SEAT_BELT_BUCKLED, SEAT_OCCUPANCY, SEAT_AIRBAG_ENABLED
  - **공조**: HVAC_TEMPERATURE_CURRENT/SET
- **표준 목록에 없는 것**: 엔진오일, 브레이크액, 워셔액, 경고등(telltale) 계열. 벤더 속성(0x2xxxxxxx, 이름 미표시)으로 제공될 수 있으나 브레이크액은 미지원 확인.
- 해석 주의: 위는 Android Automotive 표준 속성 등록 목록이며, **우리 앱이 읽을 권한이 있는지는 별도 확인 필요**. Pleos Vehicle SDK의 도메인과 1:1로 대응하지 않음.

## 3. 기획서에 주는 시사점
1. **주행 상태 게이트**: 주차 브레이크·기어·속도가 표준 속성으로 존재 → Pleos SDK가 아닌 Android Automotive 표준 API(CarPropertyManager)로 읽을 가능성. **권한·접근 가능 여부를 테스트 코드로 검증 필요.** (Vehicle SDK에는 기어·속도가 없음: 샘플 README에서 확인)
2. **내연기관 부품 시나리오(점화플러그·엔진오일)**: 이 에뮬레이터(EV)에서는 실제 데이터로 시연 불가 → 모의 데이터 또는 로드맵. 기획서의 "차종별 `checkCapabilities` 분기" 설계는 필요성이 입증됨.
3. **시연에 쓸 수 있는 후보**(미확인 항목 검증 후 확정): 주행거리(Odometer), EV 배터리 잔량, 램프·와이퍼 상태, 도어·윈도우·안전벨트, 타이어 경고.
4. **주행거리 값 주입**: 시연용 값이 필요함 → adb로 차량 속성 주입 가능 여부 시도 필요(예: PERF_ODOMETER 0x11600204).

## 4-2. 주행 상태 읽기 테스트 결과 (2026-11-07, `DrivingStateProbe`)
방식: 샘플 앱 로컬 사본에 진단 코드(`explorer/DrivingStateProbe.kt`) 추가. Android Automotive 표준 `CarPropertyManager`를 리플렉션으로 호출, 읽기 전용. 실행 `adb shell am start -n ai.pleos.playground.sample.vehicle/.MainActivity --ez probe true` → `adb logcat -d -s PleosProbe:I`. 3회 반복 실행, 결과 동일.

| 항목 | 결과 |
|---|---|
| 기어 (GEAR_SELECTION, CURRENT_GEAR) | **읽기 성공** 값 4 = PARK, 변경 이벤트 구독 가능 |
| 주차 브레이크 (PARKING_BRAKE_ON) | **읽기 성공** 값 false, 구독 가능 |
| 속도 (PERF_VEHICLE_SPEED) | **읽을 수 없음**: `android.car.permission.CAR_SPEED`가 앱에 부여되지 않고(`pm grant`로도 불가), 속성 목록에 노출되지 않음 |
| 점화 상태·주행거리(표준) | 목록에 없음 (주행거리는 Pleos Vehicle SDK로 읽음) |
- 앱 최종 판정: `drivingStateGate=USABLE`, 정차 판단은 **기어(P)와 주차 브레이크**로 가능. 속도는 쓰지 않는다.
- **기어 변경 검증 (2026-11-08)**: Virtual Console(`adb forward tcp:8088 tcp:8088` → http://127.0.0.1:8088/)의 `PUT /vehicle/gear?gear=Drive|Park`로 기어를 바꿔 확인. Drive 선택 시 `GEAR_SELECTION`이 4→**8(DRIVE_1)** 로 바뀌고 변경 이벤트가 수신됨, 판정 `parked=false`. Park으로 되돌리면 `parked=true`. **`CURRENT_GEAR`는 Drive에서도 PARK(4)로 유지**(속도 0이라 실제 기어가 안 바뀐 것으로 추정, 미확인) → 정차 판단은 **`GEAR_SELECTION` 기준**, 둘 중 하나라도 P가 아니면 주행으로 본다.
- **Virtual Console 연결 조건**: 에뮬레이터가 꺼졌다 켜지면 포트 포워딩이 사라진다(`adb forward tcp:8088 tcp:8088` 재실행). 또 콘솔은 **브라우저 페이지가 열려 있는 동안만**(페이지가 1초마다 `POST /browser/session?client=..` 신호 전송) 에뮬레이터와 연결되며, 브라우저를 닫으면 `503 emulator_inactive`가 된다. 이 신호를 스크립트로 보내면 브라우저 없이도 `PUT /vehicle/gear?gear=Drive|Park` 등을 호출할 수 있다.
- **플랫폼 주행 제한 확인**: 기어 D에서 Pleos 차량 화면이 앱 실행을 막고 "주행 중에는 사용할 수 없습니다."를 표시, P에서는 앱이 열린다(스크린샷·녹화 확보).
- Virtual Console 카탈로그에는 Odometer(`perf-odometer`)·Tire Pressure(`tire-pressure`, kPa)·Telltales 시뮬레이터가 있어 **주행거리·타이어압·경고등 값을 시연용으로 설정할 가능성**이 있음(미시험).
- 한계: ① adb `inject-vhal-event`는 user 빌드라 사용 불가 ② 실차·앱마켓 배포 시 동일 권한이 주어지는지는 주최 측 확인 필요(표준 `android.car` API 사용이라 Pleos 공식 SDK 범위 밖).

## 6. 서비스 설계에 주는 시사점
1. **오일류·워셔액·브레이크액·연료 계열은 이 에뮬레이터에서 전부 미지원** → 이 데이터에 의존하는 판단은 시연 불가(모의 데이터 또는 로드맵).
2. **트립(주행시간·거리) 계열 미지원**, 현재 주행거리만 가능 → 부품 수명은 "누적 주행거리 + 사용자 입력 이력"으로 계산.
3. **램프·와이퍼·윈도우·도어·좌석은 상태(READ)와 스위치(READ_WRITE)가 함께 존재** → "명령은 ON인데 상태는 OFF" 같은 **명령-상태 불일치**로 전구·퓨즈 이상을 짚는 시나리오가 SDK 데이터로 근거를 가질 가능성. (실제 값 읽기·불일치 재현은 추가 검증 필요)
4. **타이어 저압 경고(READ)**, **EV 배터리 잔량**, **좌석 점유·안전벨트**, **조향각**, **방향지시등**, **브레이크 페달**은 안전·상태 시나리오에 사용 가능.
5. 경고등(Telltales)·타이어 공기압 값은 샘플이 차단한 API라 **본 스캔 대상이 아님**. 사용 가능 여부는 주최 측 확인 필요.

## 7. 값 읽기 검증 결과 (2026-10-24, 읽기 전용 `get…` 호출 104건)
방식: 스캐너 2단계. 1단계에서 얻은 영역(바퀴·창문·좌석·도어 등)으로 읽기 함수를 호출. 값 변경·구독은 호출하지 않음.
- 결과: 성공 62 / 실패 38 / 건너뜀 4 (건너뜀은 단위 파라미터가 필요한 HvacTemperatureCurrent)
- 실패의 대부분은 `area ID: 0x… not supported for property ID: …` — 지원 확인이 보고한 영역 중 일부가 실제 속성에서는 미지원. 앱은 **영역별로 성공 여부를 확인**해야 함.

### 해석 주의
1. **스위치와 상태는 정상일 때도 다를 수 있음** (하이빔 스위치 OFF·상태 ON). "스위치 ON인데 상태 OFF = 전구·퓨즈 이상"은 단독 근거로 쓸 수 없고 보조 신호로만 사용.
2. 에뮬레이터는 고장 상황을 만들지 못하므로 이상 시나리오는 모의 값으로 시연.
3. 타이어 값 137.0의 의미를 문서·주최 측으로 확인해야 함. 경고 여부(boolean)가 아님.
4. 좌석 점유·안전벨트는 실제 값이 읽힘 (안전 기능 후보, 범위 관리상 보류).
